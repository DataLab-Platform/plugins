# Contributing a plugin to the catalog

Listing a plugin takes a public GitHub repository, a GitHub release holding the wheel, and a pull request adding one YAML file. No PyPI account is needed.

## Requirements

- The source code is public on GitHub and licensed under an OSI-approved license, declared in the wheel metadata (`license = "..."` in `pyproject.toml` with setuptools 77 or later). Accepted licenses: 0BSD, AFL-3.0, Apache-2.0, BSD-2-Clause, BSD-3-Clause, BSL-1.0, CECILL-2.1, EPL-2.0, EUPL-1.2, GPL-2.0 and 3.0, ISC, LGPL-2.1 and 3.0, MIT, MPL-2.0, PSF-2.0, Unlicense, Zlib.
- The plugin is distributed as a single pure-Python wheel (`*-py3-none-any.whl`), without compiled code.
- The wheel declares its plugin class in the `datalab.plugins` entry-point group (DataLab desktop) and/or `datalab.web_plugins` (DataLab-Web).
- Its requirements must be satisfied by DataLab (for example `datalab-platform`, `sigima`, `numpy`, `scipy`) or, for Desktop, by explicitly listed dependency wheels. Existing host package versions cannot be replaced. Additional wheels may contain native libraries but must cover the intended Python/ABI/platform; no compilation or system installation is performed. Web requirements remain restricted to packages supplied by the Web host.
- The plugin ID is the `id` of the plugin's `PluginInfo`. Prefer a reverse-domain name that you control, such as `io.github.<your-account>.<plugin>`. The `org.datalab.` prefix is reserved for DataLab-Platform plugins.

Projects created with `datalab-plugin create` already follow these rules.

## Source organization is not the distribution format

A plugin may be developed as a single `datalab_<name>.py` module or as a larger Python package. Both use the same plugin API and may expose the same functional capabilities. The layered project generated by `datalab-plugin create --project` is one convenient organization, not a catalog requirement.

The catalog currently accepts wheel distributions only. A wheel may contain just one module: packaging it does not require adopting the layered project. Desktop can also load or install a raw single-file plugin, but listing that `.py` file directly in an online or offline catalog is not yet supported.

## Additional Desktop dependencies

Put the plugin wheel in a local catalog folder and run `datalab-plugin catalog prepare <folder>` from the target reference environment. This authoring command uses pip to resolve and download missing dependencies, including transitive dependencies, into the folder's `dependencies` subdirectory without installing them. It prints the `dependency_wheels` YAML entries to add to the plugin release. Preparing the wheelhouse needs network access; installing the complete local catalog does not.

Each dependency entry names its wheel, upstream HTTPS URL and reviewed SHA-256:

```yaml
releases:
  - version: 1.0.0
    sha256: <plugin digest>
    dependency_wheels:
      - filename: example_dependency-1.0.0-py3-none-any.whl
        url: https://files.example.org/example_dependency-1.0.0-py3-none-any.whl
        sha256: <dependency digest>
```

The CI checks and mirrors these artifacts without executing them. The Desktop client downloads only compatible wheel tags, verifies the files, and resolves against its actual host using the local wheelhouse only. A missing transitive artifact or version conflict causes a refusal, not an implicit download from PyPI. Prepare and include wheels for each intended environment; do not assume that one native wheel supports all desktop installations. Respect the redistribution, license-notice and corresponding-source obligations of every dependency.

## Submitting a plugin

1. Build the wheel (`python -m build`) and attach it to a GitHub release of your repository, tagged `v<version>` (for example `v1.0.0`).
2. Fork this repository and add `plugins/<id>.yaml`:

   ```yaml
   # yaml-language-server: $schema=../schema/plugin-entry.schema.json
   id: io.github.alice.spectrum-tools
   name: Spectrum Tools
   repository: https://github.com/alice/datalab-spectrum-tools
   capabilities: [processing]
   keywords: [spectroscopy, baseline]
   releases:
     - version: 1.0.0
   ```

3. Open a pull request. The CI downloads and checks the wheel. The first run fails and prints the line to add to the release, such as `sha256: 3f2a...`: add it and push again.

A wheel published on PyPI may be listed instead of a GitHub release asset, with `source: pypi` and `distribution: <name>` in the release.

### Optional icon

To display an existing plugin icon in the web catalog, add its HTTPS image URL once, at the plugin level:

```yaml
icon: https://raw.githubusercontent.com/alice/datalab-spectrum-tools/main/src/spectrum_tools/icons/plugin.svg
```

SVG and PNG are recommended; any image format supported by browsers may be used. On GitHub, use the raw file URL, not a `github.com/.../blob/...` page. No particular file name, location or hosting provider is required, and there is no need to copy the image here or publish a new plugin version.

The browser loads the icon directly from its host, without sending a referrer. The catalog build does not download or check the image. Initials are displayed when no icon is declared, when it cannot be loaded, or when JavaScript is disabled. If the file moves, update its URL; a branch URL can update the icon independently of plugin releases, subject to browser caching.

## Publishing a new version

Add the version, with its `sha256`, at the end of `releases` and open a pull request. Every new version is reviewed before it is published: keep the previous versions listed.

## Withdrawing a version or a plugin

- `yanked: <reason>` in a release tells DataLab not to install it.
- `status: deprecated` with a `status_reason` keeps the plugin installable with a warning.
- `status: revoked` with a `status_reason` removes the downloads; DataLab warns users who installed the plugin. Maintainers revoke plugins that are malicious or seriously broken.

## Review

Maintainers check that the entry is consistent, that the plugin matches its description, and that nothing in the repository is obviously harmful. This review is not a security audit: users are told to install only plugins from authors they trust.
